# 셀핀다가바 체험형 마케팅 플랫폼 요구사항

기준일: 2026-09-10. 요구사항 기준: 사용자 제공 `goal-objective.md` 및 대화의 완제품·스토리텔링·상세 연구·실제 후기 요구. 이 문서는 구현 증거가 아니며, 아래 기능의 검증 상태는 모두 `pending`이다.

## 목표와 전체 흐름

사이트는 GABA 자료 모음이 아니라 **내 상태 발견 → GABA를 쉽게 이해 → 발효가바 신뢰 확인 → 제품 선택 → 결과 공유 → 구매**를 지원하는 체험형 마케팅 플랫폼이다. 상태 발견은 생활 습관의 자기 성찰이며 의학적 측정이 아니다. 모든 단계를 강제하지 않고 제품·근거로 바로 가는 탐색 경로도 제공한다.

이야기의 질문은 ‘오늘, 내 뇌는 쉴 틈이 있었을까?’를 출발점으로 검토한다. 사용자 문서의 문구·제품 수치·균주·특허 정보는 검토 입력이며 자동으로 공개 승인된 사실이 아니다. 대상은 원료가 아닌 **셀핀다가바 완제품**이다. 발효와 원료 출처는 완제품 신뢰를 설명하는 정보로 다룬다.

각 장면은 `이야기 한 문장 → 핵심 사실과 중요한 한계 → 비교·상세 자료 → 원문`의 네 층으로 구성한다. 데이터 밀도는 숫자 개수가 아니라 출처·대상·조건·한계를 확인할 수 있는 완결성으로 확보한다. 중요한 한계는 펼침 내부에 숨기지 않는다.

## 상세 연구와 후기: 1차 콘텐츠 필수 요구

### 연구 라이브러리

홈 요약, GABA 스토리, 발효기술, 제품 경험, 리듬 연구소에서 필요한 상세 정보로 이동할 수 있어야 한다. 각 자료는 독립 링크를 가지며 원문을 열 수 있어야 한다. 원문 비공개 자료는 공개 승인된 요약과 확인 문의 경로를 제공한다.

연구 데이터 필드: 제목, 저자·발행기관, 연도, 원문 URL·DOI, 자료 유형(인체·동물·기전·시험·제품문서), 연구 대상과 표본, 제형·용량·기간·대조 조건, 측정 지표, 주요 결과, 효과 크기·불확실성(원문에 있을 때), 한계, 해당 완제품 적용 여부, 검토자·검토일·승인 상태. 없는 필드는 추정하지 않는다.

일반 GABA 연구와 셀핀다 완제품 자료를 시각적으로 구분한다. 제목·그림·CTA 배치까지 검토하며 면책 문구 하나로 광고 검토를 대체하지 않는다. 흥미로운 긍정 결과만 선정하지 않고 관련 한계·상반된 결과도 맥락에 포함한다. 상세 정보는 펼침으로 제공하되 자료 유형과 제품 적용 한계는 기본 노출한다.

### 실제 사용 후기

홈의 선별 후기에서 전체 후기와 원문으로 이동한다. 연구 결과 바로 옆에 후기를 붙여 연구 입증 사례처럼 연출하지 않는다. 후기의 개인 경험은 제품 효과 검증과 구분한다.

후기 데이터 필드: ID, 원문, 출처 플랫폼·URL, 작성일, 실제 제품·구성, 작성자가 밝힌 사용 기간·상황, 공개명, 공개·재사용 권한, 구매 확인 방법, 제품 제공·대가·광고 관계, 편집 요약·발췌 여부, 주제, 검토자·검토일, 승인·철회 상태. 모르는 제품·기간·광고 여부를 만들어 채우지 않는다.

대표 후기 선정 기준을 표시한다. 충분한 데이터가 있을 때 제품·주제·기간·제공 여부 필터를 제공한다. 표본 근거 없는 평균점수·만족률·후기 수, 가짜 인물·후기 금지. 부정적 경험도 일관된 게시 정책으로 처리하고 수정·삭제 요청을 기록한다. 원문에 개인 건강정보가 있으면 필요한 공개 범위만 승인받는다.

## 정보 구조와 시각 경험

- 홈: 공감 → 체크 → GABA 이해 → 발효 신뢰 → 실제 경험·제품 선택 → 결과 공유·구매. 연구와 후기의 상세 탐색 경로를 유지한다.
- GABA 스토리: 일반 개념, 신호 균형, 식품과 발효, FAQ, 근거 원문.
- 셀핀다 발효기술: 균주, 공정, 분석·표준화, 특허·기탁·시험, 출처 추적.
- 제품 경험: 현재 가바750·1500 구성, 맛·섭취 방식·실물 크기·표시사항·공식 구매.
- 리듬 연구소: 체크, 생활 루틴, 쉽게 읽는 연구, 카드뉴스·숏폼. 2차 챌린지로 확장.
- 공유: 결과 카드, 플랫폼별 가능한 공유 경로. 2차 친구 초대·추천 내역·혜택으로 확장.

깨끗한 흰 배경, 확인된 브랜드 컬러, 발효를 연상시키는 보조색을 사용한다. 실제 제품·일상·공정 이미지에 사용권을 확인한다. 한 화면의 주요 메시지는 하나로 유지하고 데이터 상세 접근을 희생하지 않는다. 자동 슬라이드·강제 스크롤 없이 키보드 탐색, 이미지 대체텍스트, 명확한 포커스, 동작 줄이기를 지원한다. 360px 모바일부터 본문 가로 넘침과 고정 요소의 내용 가림을 검증한다.

## 이벤트와 지표 계약

## 비진단·공유 개인정보 기준

체크는 체내 GABA 수치·결핍·질환·위험도를 측정하지 않는다. 결과에서 보충제 필요성, 증상별 용량, 치료 효과를 추론하지 않는다. 일반 생활 안내와 구매 선택을 분리하고 결과 규칙 버전을 기록한다.

1차 답변은 기본적으로 브라우저 메모리에서 처리한다. 서버에 응답 원문을 저장해야 하는 변경은 목적·최소 범위·동의·삭제 정책을 먼저 설계한다. 공유 카드의 기본값에는 이름·연락처·개별 답변·점수·질환·정확한 작성시각을 넣지 않는다. 유형 공개도 미리보기에서 선택·확인하며 공유 URL에 답변을 인코딩하지 않는다. 공유한 이미지는 외부에서 회수할 수 없음을 공유 단계에서 간결하게 알린다. 계정 기록과 공개 공유 결과의 접근 권한을 분리한다.

## 서버·운영·배포 완료 게이트

1. 실제 제품·최신 표시사항·공개 자료·후기 권한·공식 구매 URL이 확인되어야 공개 문구를 승인한다.
2. 관리자 승인과 분석은 localStorage 데모로 대체하지 않는다. 서버 DB 마이그레이션·권한·재시작 후 복원·백업 복구를 확인한다.
3. 주문 연동은 서명·재전송·중복·환불·실패 재처리와 대사 확인을 포함한다. 실제 통제된 주문 또는 판매처 운영 검증 증거 없이 실구매 측정을 완료 처리하지 않는다.
4. 빌드·핵심 기능·접근성·기기·공유 이미지·OG 미리보기·판매처 링크를 검증한다. 서버만 보유해야 할 키가 클라이언트에 포함되지 않아야 한다.
5. 배포 URL·HTTPS·도메인·DB 영속 볼륨 또는 관리형 저장소·환경변수·오류 로그·롤백·운영자 접근을 실제 확인한다. 공개 URL에서 핵심 여정을 다시 검증한다.
6. 모든 pending 항목에는 담당 역할, 다음 행동, 필요한 외부 입력, 검증 증거 경로를 연결한다. 정보가 없는 항목을 임의 완료하지 않는다.
